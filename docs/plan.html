Freelancers Manager

Build plan · a smaller Sorah Ops for one person

One screen that tells a freelancer what's due, what's owed, and who to message next.

Sorah Ops runs a whole production company. This is the solo version: projects, clients, deliverables and payments. It drops crew, equipment and team permissions. It uses the same design system as Sorah Rent, with Arabic-first RTL, EGP, WhatsApp as the main channel and InstaPay / Vodafone Cash payments.

Note on the reference. This cloud session couldn't open sorah-ops-production.up.railway.app. It has no access to your Chrome, and the network proxy blocks the host. The Sorah Ops comparison below assumes the modules an agency ops tool usually has. Check that table first and tell me what Ops actually has, and I'll adjust the scope.

Project lifecycle

Work status and payment status are tracked separately
Lead · عرض سعر→ Active · شغال→ With client · عند العميل⇄ Revising · تعديلات→ Delivered · اتسلم→ Archived
No deposit→ Deposit paid→ Paid in full Overdue متأخر when a payment's due date has passed and it's still unpaid.

Revision rounds are counted (for example "Round 2 of 3"). Going from "With client" back to "Revising" adds a round. Going past the agreed number flags the project, so extra rounds can be billed.

Data model

Five records
RecordFields
Clientid, name, phone, company, notes, createdAt
Projectid, code (FM-1042), clientId, title, type, status, startDate, dueDate, fee, currency, depositPct, revisionsAllowed, revisionsUsed, deliveryLinks[], notes
Deliverableid, projectId, label, dueDate, done
Paymentid, projectId, label (deposit / balance / extra), amount, dueDate, paidAt, method (instapay / vcash / cash / bank), ref
Activityid, projectId, at, kind, text: append-only log for "sent v2", "paid deposit", "round 3 started"

Owed, overdue, payment status and the KPIs are all calculated from these records. None of them are stored, so they can't fall out of sync.

Flows that must feel fast

Target: each in under 30 seconds on a phone
FlowSteps

Send a quote"WhatsApp client" opens a pre-filled message: scope, fee, deposit, payment details.
Log a paymentTap the payment → method + reference → toast, KPIs update.
Send a versionPaste the delivery link → status becomes "With client" → WhatsApp message with the link.
Chase moneyToday → "Payments to chase" → one tap sends a polite reminder with the amount and payment details.

Build approach

  • Front end: vanilla JS + one CSS file, structured like Sorah Rent: state object, render functions, data-act event delegation. No framework.
  • v1 storage: IndexedDB on the device, plus JSON export/import as a backup. It works offline as an installable PWA.
  • v2 sync: small Node API + Postgres on Railway (same host as Sorah Ops), with one login per freelancer. Local data uploads on first sign-in.
  • Repo layout: app/ (index.html, app.css, app.js, sw.js), server/ added in v2, docs/ for this plan.

Not in v1

  • Team members, roles, permissions
  • Calendar grid and Google Calendar sync
  • Time tracking and hourly billing
  • Generated PDF invoices (v1 shows an invoice view to screenshot)
  • Client portal or client logins
  • Expenses and profit reports
